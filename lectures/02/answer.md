## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：学習エポック数（`num_train_epochs`）を **20** から **10** に変更。
- 結果（比較表や数字）：
| 評価指標 | 変更前 (Epochs=20) | 変更後 (Epochs=10) |
| :--- | :---: | :---: |
| **形式遵守率 (format_rate)** | 9.5% → 100% | 9.5% → 100% |
| **内容正解率 (content_rate)** | 0.0% → 85.7% | 0.0% → **95.2%** |
| **両方達成率 (both_rate)** | 0.0% → 85.7% | 0.0% → **95.2%** |

※ 学習前はいずれの条件でも `format_rate`: 9.5%、`content_rate`: 0.0%

#### 結果の分析
エポック数を20から10に半減させたことで、学習後における内容正解率（`both_rate`）が **85.7% から 95.2% へ向上**しました。過剰なエポック数（20周）によって発生していた過学習（Overfitting）や、未知の質問・類似表現への柔軟性の低下が、エポック数を10に調整したことで緩和されたと考えられます。なお、指定フォーマット（JSON形式）を守る割合はどちらも100%を達成しました。

- ファインチューニングが向く場面・向かない場面についての考察：
* **向く場面**:
  * **回答フォーマットや出力構造の強制**: 学習前のモデルはプロンプトの指示に従いきれず形式違反（約9.5%のみ成功）が多発していましたが、LoRA学習後はほぼ100%指示されたJSON構造で応答できるようになりました。このように特定の出力形式やスタイル、文体を統一・遵守させる用途には非常に適していると考えます。
  * 
* **向かない場面**:
  * **正確な知識の獲得・ハルシネーション（嘘の回答）の防止**: FAQに存在しない未学習の質問（例：「この講座の最終課題の締切はいつですか」）に対して、モデルは「確認が必要」と返さず、FAQ内の別の期限情報を流用して `needs_review: false` で断定的に回答してしまう事象が確認されました。モデルに事実や知識を完全に正しく保持・判断させる目的でファインチューニングを行うのは難しく、RAG（検索拡張生成）などの仕組みと併用する必要があると思われます。
